## Цель

Подготовить в ClickHouse одну воспроизводимую агрегатную таблицу для будущего графика Metabase «Выручка по дням и магазинам» и доказать совпадение её данных с детальным фактом.

**Где:** `retail_pz7.agg_daily_store_sales` (ClickHouse).  
**Зерно:** одна строка = календарный день × магазин.  
**Показатели:** `amount_sum`, `qty_sum`, `sales_rows`.

Эталонная метрика остаётся `SUM(amount)` по `retail_pz7.fact_sales` (детальные данные), а не по сводке. Архитектура и ограничения описаны в [`notes/aggregate_design.md`](notes/aggregate_design.md).

## Содержимое

- `sql/ddl_aggregate.sql`: таблица MergeTree, `Decimal(18,2)`.
- `sql/refresh_aggregate.sql`: воспроизводимый полный пересчёт `TRUNCATE` + `INSERT SELECT`.
- `sql/checks.sql`: SQL для сверки.
- `scripts/build_aggregate.py`: создание, пересчёт, контроль всей выручки, контроль января 2024 и всех групп.
- `checks/results.md`: формируется после запуска и включает историю двух запусков.

## Запуск на Windows 10

Требуется запущенный Docker Desktop и выполненная З07 (таблицы `retail_pz7`). Перейти в папку проекта:

```powershell
cd E:\OLAP
py -3.11 pz9/scripts/build_aggregate.py
```

Для проверки повторной загрузки выполнить **ту же команду второй раз**. В обоих прогонах контрольная сумма должна быть **264.00**, число строк детального факта **15**, а число строк агрегата должно остаться неизменным.

Проверка SQL напрямую:

```powershell
docker exec olap_clickhouse clickhouse-client --query "SELECT count(), sum(sales_rows), sum(amount_sum) FROM retail_pz7.agg_daily_store_sales"
docker exec olap_clickhouse clickhouse-client --query "SELECT count(), sum(amount) FROM retail_pz7.fact_sales"
```

После **каждой новой З07-загрузки** нужно повторно запустить скрипт З09: З07 пересоздаёт базу `retail_pz7` целиком, включая сводку.

## Сдача

Предоставить SQL, команду воспроизведения, файл `checks/results.md`, описание зерна и способа refresh. Сводка — отдельный оптимизированный источник графика; карточку главной метрики в З10–З11 следует сверять с запросом к детальному факту.

## Ограничение

Это **не materialized view**, а обычная агрегатная MergeTree-таблица с ручным пересчётом. При сбое между `TRUNCATE` и `INSERT SELECT` сводка может быть временно недоступна; каноническая таблица фактов не затрагивается.
