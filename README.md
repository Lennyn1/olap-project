## 1. Описание проекта

Проект выполняется в рамках дисциплины «Оперативный анализ данных (OLAP)» и предназначен для разработки аналитической витрины розничных продаж.

**Цель проекта:** разработать аналитическую систему, позволяющую оценивать выручку розничных магазинов в разрезе регионов, товаров, категорий и периодов времени.

В качестве исходных данных используется учебный набор CSV-файлов из материалов курса.

### Главная метрика

**Общая выручка (total_revenue)** — сумма денежных значений всех продаж за выбранный период.

Формула:

`total_revenue = SUM(amount)`

Где `amount` — сумма продажи из таблицы `fact_sales`.

Эталонный SQL-запрос:

```sql
SELECT SUM(amount) AS total_revenue
FROM retail_dw.fact_sales;
```

Для исходного учебного набора данных общая выручка составляет **264,00 условных денежных единиц**.

Главная метрика сохраняется неизменной на протяжении всех практических работ З01–З12.

## 5. Установка и запуск стенда

### 5.1. Предварительные требования

Для запуска необходимы:

- Windows 10 с поддержкой WSL 2;
- Docker Desktop;
- Git Bash для запуска Bash-скриптов;
- Python 3.11;
- Git.

### 5.2. Запуск Docker-контейнеров

Перед запуском необходимо открыть Docker Desktop и дождаться готовности Docker Engine.

В PowerShell перейти в каталог стенда:

```powershell
cd E:\OLAP\Стенд
```

Запустить контейнеры:

```powershell
docker compose -p olap up -d
```

Проверить состояние контейнеров:

```powershell
docker compose -p olap ps
```

Стенд включает два основных сервиса:

- `olap_clickhouse` — аналитическая база данных ClickHouse;
- `olap_metabase` — система визуализации Metabase.

### 5.3. Используемые порты

| Сервис | Порт | Адрес |
|---|---|---|
| ClickHouse HTTP | 8123 | http://localhost:8123 |
| ClickHouse Native | 9000 | localhost:9000 |
| Metabase | 3000 | http://localhost:3000 |

### 5.4. Проверка ClickHouse

В PowerShell выполнена команда:

```powershell
curl.exe http://localhost:8123/ping
```

Полученный результат:

```text
Ok.
```

Ответ `Ok.` подтверждает успешный запуск ClickHouse и доступность HTTP-интерфейса.

### 5.5. Инициализация базы данных

Для создания таблиц и загрузки CSV-файлов используется скрипт `scripts/init_ch.sh`.

Из корневой папки стенда через Git Bash выполняется:

```bash
bash scripts/init_ch.sh
```

Скрипт выполняет следующие действия:

1. Проверяет доступность ClickHouse.
2. Создаёт базу данных `retail_dw`.
3. Создаёт аналитические таблицы.
4. Загружает данные из `data/sample/`.
5. Выводит количество записей в таблицах.

Схема базы описана в `init/01_schema.sql`.

### 5.6. Проверка загруженных данных

Для проверки таблицы продаж выполнена команда:

```powershell
docker exec olap_clickhouse clickhouse-client --query "SELECT count() FROM retail_dw.fact_sales"
```

Полученный результат:

```text
15
```

Таким образом, таблица `retail_dw.fact_sales` содержит 15 записей.

### 7.5. Связи между таблицами

В учебной модели используется структура «звезда» (Star Schema).

Центральная таблица фактов — `fact_sales`.

Она связана с тремя измерениями:

- `dim_date` — по полю `date_id`;
- `dim_product` — по полю `product_id`;
- `dim_store` — по полю `store_id`.

Предварительно принимается, что одна строка таблицы `fact_sales` представляет отдельную запись о продаже конкретного товара в определённом магазине и в определённую дату.

Окончательное описание зерна модели будет оформлено в практической работе З02.

## 8. Планируемые аналитические запросы

### Общая выручка

```sql
SELECT SUM(amount) AS total_revenue
FROM retail_dw.fact_sales;
```

### Выручка по регионам

```sql
SELECT
    s.region,
    SUM(f.amount) AS revenue
FROM retail_dw.fact_sales AS f
JOIN retail_dw.dim_store AS s
    ON f.store_id = s.store_id
GROUP BY s.region
ORDER BY revenue DESC;
```

### Выручка по категориям товаров

```sql
SELECT
    p.category,
    SUM(f.amount) AS revenue
FROM retail_dw.fact_sales AS f
JOIN retail_dw.dim_product AS p
    ON f.product_id = p.product_id
GROUP BY p.category
ORDER BY revenue DESC;
```

### Выручка по месяцам

```sql
SELECT
    d.year,
    d.month,
    SUM(f.amount) AS revenue
FROM retail_dw.fact_sales AS f
JOIN retail_dw.dim_date AS d
    ON f.date_id = d.date_id
GROUP BY d.year, d.month
ORDER BY d.year, d.month;
```

Эти запросы являются основой для дальнейшего OLAP-анализа и построения дашборда.
