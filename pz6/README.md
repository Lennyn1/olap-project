## Задача и модель

В исходной витрине З03 товар имеет один `product_id` и одну текущую категорию. Если категорию перезаписать (SCD1), исторические продажи будут ошибочно относиться к новому разделу. В З06 создаётся отдельная демонстрационная DuckDB-витрина с версионным `dim_product_scd2` и `fact_sales_scd2`. **Это демонстрация, не изменение действующих данных З03–З05**.

- Натуральный ключ товара: `product_id`.
- Суррогатный ключ версии: `product_sk`.
- Период действия: `[valid_from, valid_to)`; `valid_to IS NULL` означает действующую версию.
- Факт ссылается на `product_sk`, выбранный по дате продажи: `valid_from <= full_date AND (valid_to IS NULL OR full_date < valid_to)`.

Учебный сценарий: у товара `product_id = 101` категория меняется **с 2024-02-01** с «Молочка» на «Свежее молоко». Это **искусственное изменение** для проверки SCD2, а не факт из CSV. Январские продажи должны остаться в категории «Молочка».

## Запуск на Windows 10

1. Убедиться, что З03/З05 уже создала базу `pz3/retail_local.duckdb`.
2. В PowerShell из `E:\OLAP` выполнить:

```powershell
py -3.11 pz6/scripts/run_scd2.py
```

При необходимости восстановить исходную витрину командой `py -3.11 pz5/etl/load.py`.

## Доказательства для преподавателя

- `sql/scd2_ddl.sql` — DDL двух таблиц.
- `sql/checks.sql` — запросы для просмотра версий, фактов и отчёта.
- `checks/results.md` — реальные результаты, создаются **только после успешного запуска**.
- По товару №101 видны две версии, в фактах используются обе версии `product_sk`.
- Историческая выручка по категориям за январь до и после изменения совпадает, суммарная выручка проекта остаётся 264.00 (если набор данных не изменён).

Скрипт можно повторить: демонстрационная база пересоздаётся с нуля, не накапливая дубликаты. При ошибке проверок рабочая витрина не затрагивается.

## Ограничения

В исходных CSV нет истории смены категорий. Поэтому здесь показан **учебный сценарий изменения**, а не восстановление реальной истории. Промышленный SCD2-процесс для каждого последующего CSV-обновления пока не реализован; он может потребовать отдельного журнала изменений и правила выбора версии на момент продажи. В остальных измерениях сохраняется исходное решение: `dim_store.store_name` — SCD1, `dim_date` не версионируется.
