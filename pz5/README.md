## Задача

Создать воспроизводимую загрузку из исходных CSV в модель «звезда» DuckDB. На входе используются `Стенд/data/raw/*.csv` из З01, структура таблиц берётся из `pz3/sql/ddl_duckdb.sql`, а эталон метрики — `pz4/sql/canonical_metric.sql`. Одна строка `fact_sales` — одна запись о продаже конкретного товара в магазине в определённую дату; `sale_id` — уникальный идентификатор записи (номер чека неизвестен).

## Пайплайн

`CSV (raw) → TEMP stg_* (все поля VARCHAR) → quality checks → dim_date/dim_store/dim_product → fact_sales → проверка counts/sum → публикация файла DuckDB`

Вместо удаления строк из существующих таблиц скрипт собирает **новую временную базу**, затем после всех проверок заменяет прежнюю `pz3/retail_local.duckdb`. Это идемпотентный *full refresh*: при повторе заново пересоздаётся вся витрина, поэтому продажи не удваиваются. Если любая проверка падает, старый файл базы остаётся без изменений. Это также обходит ограничения DuckDB на `DELETE` из справочников, на которые ссылаются факты.

Команду запускаем **дважды подряд**. После каждого запуска консоль сообщает число строк в таблицах, `SUM(amount)` и статус проверок. Оба запуска дописываются в `pz5/checks/run_log.md` (лог создаётся автоматически, заранее его не нужно редактировать).

Для неизменённого sample ожидается: `dim_date=8`, `dim_store=5`, `dim_product=8`, `fact_sales=15`, `SUM(amount)=264.00`. При другом корректном наборе исходных данных числа могут отличаться.

## Quality checks

1. **Null/blank:** обязательные поля источника и ключи не пустые.
2. **Range/type:** даты в 2000–2100 гг., месяц 1–12, день недели 1–7, qty ≥ 0, amount ≥ 0, ключи корректного числового типа.
3. **Duplicates:** уникальны `sale_id`, `date_id`, `store_id`, `product_id` в соответствующих таблицах. Несколько разных `sale_id` с одинаковыми товаром/датой/магазином допустимы: в сырье нет номера чека и нельзя считать их доказанными дублями.
4. **FK:** каждая ссылка `date_id`, `store_id`, `product_id` из факта существует в соответствующем справочнике.

При любом нарушении выполнение останавливается с **exit code 1** и **новая база не публикуется**. При успехе `exit code 0`.

Проверка отказа на искусственно испорченном CSV (не изменяет настоящие файлы):

```powershell
py -3.11 pz5/etl/test_bad_data.py
```

Тест временно меняет `qty` на `-1` в копии `fact_sales.csv`, запускает загрузку на отдельном временном пути и должен показать `PASS: invalid qty rejected`.
