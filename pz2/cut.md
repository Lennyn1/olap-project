## 1. Назначение документа

Документ определяет функциональность, которая сознательно не включается в семестровый OLAP-проект, причины ограничений и их последствия для аналитической отчётности.

Основная цель проекта — построение аналитической витрины розничных продаж с использованием DuckDB, ClickHouse и Metabase.

Главная метрика проекта — общая выручка `SUM(amount)`.

## 2. Ограничения проекта

| Что не делаем | Причина | Цена отказа для аналитики |
|---|---|---|
| Кластер ClickHouse, репликация и отказоустойчивость | Используется локальный учебный стенд | При сбое сервера аналитические запросы и дашборд могут стать недоступны |
| Kafka и потоковая загрузка | Исходные данные представлены небольшими CSV-файлами | Отчёты обновляются только после пакетной загрузки; нет аналитики в реальном времени |
| Обучение ML/Data Mining модели | Проект ориентирован на описательную аналитику | Нет автоматического прогнозирования спроса или сегментации покупателей |
| Анализ чеков и среднего чека | В исходных данных отсутствует `receipt_id` | Невозможно достоверно определить количество чеков, средний чек и состав покупательских корзин |
| Учёт возвратов, скидок и налогов | Соответствующие поля отсутствуют в исходных CSV | Невозможно корректно рассчитать чистую выручку после возвратов или показатели с учётом налогов и скидок |
| Подтверждённая валюта | В исходных данных отсутствует обозначение валюты | Выручка рассчитывается в условных денежных единицах |
| Сложное управление доступом и аналитика клиентов | В учебном наборе нет клиентского измерения | Недоступны анализ покупателей, персонализация и полноценная проверка разграничения доступа |

## 3. История изменения справочников (З06)

Для атрибута `dim_product.category` реализована учебная демонстрация **SCD Type 2**.

Демонстрация находится в `pz6/` и использует отдельную базу данных `scd2_demo.duckdb`.

В рамках З06:

- Созданы исторические версии товара с суррогатным ключом `product_sk`.
- Используются поля `valid_from`, `valid_to` для периодов действия версий.
- Продемонстрирована смена категории товара `product_id = 101` с «Молочка» на «Свежее молоко».
- Факты связаны с соответствующими версиями товара.
- Подтверждено, что январский отчёт не меняется после появления новой категории.

**Ограничение:** SCD2 реализован как отдельная учебная демонстрация. Основная витрина З03–З05 и таблицы ClickHouse из З07 пока используют обычный справочник `dim_product` без хранения исторических версий.

**Цена ограничения:** если категория товара изменится в основной витрине, историческая выручка по категориям может перераспределиться в соответствии с новым значением категории.

Таким образом, механизм SCD2 продемонстрирован, но его полноценная интеграция в основную аналитическую систему не входит в текущий объём проекта.

## 4. Отказ от партиционирования ClickHouse (З08)

Для таблицы `retail_pz7.fact_sales` не используется месячное партиционирование `PARTITION BY`.

**Причина:** учебная таблица фактов содержит всего 15 строк. Разделение такого небольшого объёма на месячные партиции не принесёт существенной пользы и усложнит структуру хранения данных.

Используется следующий ключ сортировки:

```sql
ORDER BY (date_id, store_id, product_id)
```

Он соответствует характерным запросам проекта с фильтрацией по датам, магазинам и товарам.

`ORDER BY` определяет порядок хранения данных и помогает работе первичного индекса MergeTree. Он не обеспечивает уникальность строк и не заменяет партиционирование.

**Цена отказа:** при значительном увеличении объёма исторических данных станет менее удобно удалять, перезагружать и обслуживать отдельные месяцы или другие временные интервалы.

**Условие пересмотра:** если проект перейдёт от небольшого учебного набора к большим историческим данным, следует повторно рассмотреть месячное партиционирование, например по `toYYYYMM(full_date)` с учётом структуры таблицы фактов и используемых дат.
