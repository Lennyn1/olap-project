## Цель и архитектура

`Стенд/data/raw/*.csv` → `pz5/etl/load.py` (staging, проверка качества, публикация DuckDB) → `pz7/etl/load_clickhouse.py` (MergeTree, ClickHouse `retail_pz7`) → `pz9/scripts/build_aggregate.py` (сводка день × магазин) → `pz10` (4 SQL-вопроса, дашборд Metabase) → `pz11` (сверка SQL = BI).

**Зерно факта:** одна запись продажи одного товара в одном магазине на конкретную дату; уникальный идентификатор записи `sale_id`, номера чека нет. **Мера:** `SUM(amount)` по детальной `retail_pz7.fact_sales`, Decimal(12,2), без фильтров на учебном наборе — **264,00 условных денежных единиц**. DuckDB — локальная лаборатория; источник Metabase — ClickHouse.

## Подъём и проверка — 5 шагов (Windows 10, PowerShell)

Перед началом нужны Docker Desktop, Python 3.11 с `duckdb`, исходная папка `Стенд/data/raw/`, каталоги `pz2`–`pz11`. Команды выполнять из `E:\OLAP`, кроме перехода в стенд.

**1. Поднять стенд:**

```powershell
cd E:\OLAP\Стенд
docker compose -p olap up -d
cd E:\OLAP
```

**2. Проверить raw и получить лабораторную DuckDB-витрину (quality-first ELT):**

```powershell
py -3.11 -m pip install duckdb
py -3.11 pz5/etl/load.py
```

**3. Перенести данные в ClickHouse и ОБЯЗАТЕЛЬНО обновить агрегат:**

```powershell
py -3.11 pz7/etl/load_clickhouse.py
py -3.11 pz9/scripts/build_aggregate.py
```

`pz7` пересоздаёт **только** базу `retail_pz7`, поэтому удаляет ранее созданный агрегат З09. Порядок З07 → З09 обязателен. Повторная загрузка не должна удваивать строки. Если нужно показать исторические изменения справочника, отдельно запускается `py -3.11 pz6/scripts/run_scd2.py` — это **не** часть основной CH-витрины.

**4. Проверить канон и открыть Metabase:**

```powershell
docker exec olap_clickhouse clickhouse-client --query "SELECT count(), sum(amount) FROM retail_pz7.fact_sales"
py -3.11 pz12/scripts/check_contour.py
```

Ожидается `15` и `264` / `264.00`; контрольный SQL: `pz11/sql/canonical_metric.sql` (также `pz4/sql/canonical_metric.sql` в DuckDB). Затем открыть **http://localhost:3000** → сохранённый дашборд **«Анализ розничных продаж»** (точное имя в интерфейсе может отличаться). 4 карточки: выручка, регионы, категории, дни × магазины; общий фильтр периода. Скрипт **не** проверяет UI автоматически, это ручной этап.

**5. Проверить сохранённый протокол SQL = BI и сообщения ошибок:**

```powershell
Get-Content pz12/checks/results.md
Get-Content pz11/checks/results.md
```

При финальном протоколе З11 значения из Metabase вводятся вручную командой `py -3.11 pz11/scripts/verify_sql_bi.py --bi-all 264 --bi-jan <ФАКТИЧЕСКОЕ_ЧИСЛО>` (подробности в `pz11/README.md`). **Не запускайте `verify_sql_bi.py` без аргументов после уже выполненной З11, если хотите сохранить существующий итоговый PASS:** этот запуск может перезаписать протокол статусом ожидания. В таком случае достаточно прочитать существующий `pz11/checks/results.md`.

## Где смотреть, если что-то красное

- Docker: `docker ps`, `docker logs olap_clickhouse --tail 50`, `docker logs olap_metabase --tail 50`.
- З05: `pz5/checks/run_log.md` и `py -3.11 pz5/etl/test_bad_data.py`.
- З07: `pz7/checks/results.md` (DuckDB ↔ CH), З09: `pz9/checks/results.md` (агрегат ↔ факт).
- З10: `pz10/checks/results.md`, SQL карточек: `pz10/dashboards/*.sql`.
- З11: `pz11/checks/results.md`; фильтры должны быть одинаковыми и карточка должна читать детальную таблицу.
- HTTP 403 ClickHouse при входе из Metabase: требуются отдельные правильные сетевые учётные данные (например `metabase_reader` с SELECT). Не подставлять логин Metabase вместо логина ClickHouse; не удалять Docker volumes. Подробнее `pz10/README.md`.
- В `/plugins` Metabase 0.52.16 нужен совместимый драйвер ClickHouse. Установка драйвера и настройка подключения — **ручные действия, не воспроизводимые одной командой**. Пароли не коммитить.

## Ограничения полной воспроизводимости

Этот README воспроизводит **данные** из CSV при наличии Python, Docker и исходных файлов, но НЕ восстанавливает автоматически сохранённые Metabase-вопросы, дашборд, их привязки фильтров, драйвер и пользовательские учётные данные. Они живут в локальном хранилище Metabase. При новом пустом томе их придётся создать по `pz10/README.md` и `pz10/dashboards/`. Для защиты покажите уже настроенный локальный контейнер или пересоздайте UI по инструкции. Непроверенный прогон на совершенно чистом ПК в зачётном чеклисте не заявлен как PASS.

## Устный рассказ (1–2 минуты)

«Мы анализируем розничные продажи. Исходные данные — четыре CSV: даты, магазины, товары и зарегистрированные строки продаж. Каждая строка факта — одна продажа одного товара в определённом магазине и дате; чека как отдельного объекта здесь нет. Сначала ELT в З05 загружает данные во staging, проверяет обязательные поля, диапазоны, дубли и связи справочников с фактом и только после этого публикует DuckDB-витрину. В З07 переносим те же данные в ClickHouse, используя MergeTree и Decimal для денежной меры. В факте `ORDER BY (date_id, store_id, product_id)` соответствует фильтрам по времени и магазинам и помогает первичному индексу, но не запрещает дубли — это не уникальный первичный ключ OLTP. Месячные партиции для 15 строк не нужны, что объяснено в `cut.md`. З09 считает отдельную сводку: одна строка — день и магазин, показатель — сумма выручки; сводка обновляется полным пересчётом после загрузки фактов. Главная метрика не в сводке, а в детальной таблице: `SUM(amount)`, всего 264,00. Metabase подключается к ClickHouse, показывает четыре виджета с общим фильтром дат. В З11 мы сверили карточку и SQL на одинаковых периодах. SCD2 категорий продемонстрирован отдельно в З06 и честно отмечен как ограничение основной витрины».
