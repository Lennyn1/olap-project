# З11 — SQL и карточка — одно число

**Дисциплина:** Оперативный анализ данных (OLAP)  
**Студент:** Лежень А.В. · **Группа:** 233  
**Проект:** D1 — Розница / Анализ розничных продаж

## Цель

Подтвердить, что **общая выручка `SUM(amount)`** в ClickHouse и карточке «Общая выручка» дашборда З10 совпадает **при одинаковых фильтрах**. Канон хранится в `sql/canonical_metric.sql` и использует только детальную таблицу `retail_pz7.fact_sales`. Без фильтров ожидается **264.00** условных денежных единиц.

## Файлы

- `sql/canonical_metric.sql` — эталон без фильтра; не заменять запросом к агрегату.
- `sql/revenue_january_2024.sql` — тот же SUM(amount), дата продажи — январь 2024.
- `scripts/verify_sql_bi.py` — реальные запросы к ClickHouse и сверка с вручную указанными значениями карточки.
- `checks/results.md` — автоматически создаваемый протокол; **не считать PASS без реальной проверки в Metabase**.
- `checks/README.md` — контрольный список.

## Шаг 1. Получить эталон из ClickHouse

Docker Desktop должен быть запущен. В PowerShell из каталога `E:\OLAP`:

```powershell
py -3.11 pz11/scripts/verify_sql_bi.py
```

Скрипт покажет два числа из ClickHouse и сохранит **предварительный** `checks/results.md` с пометкой «Ожидает ручной проверки», пока значения из Metabase не переданы. HTTP-пароль ClickHouse не нужен: скрипт использует `docker exec olap_clickhouse clickhouse-client`, как в З07–З10.

## Шаг 2. Получить числа из Metabase

1. Открыть <http://localhost:3000> → дашборд «Анализ розничных продаж» → карточка **«Общая выручка»**.
2. Сбросить все фильтры. Переписать отображаемое число **B1** (ожидается 264 или 264.00).
3. Выбрать **Период продаж: с 01.01.2024 по 31.01.2024 включительно**, остальные фильтры оставить пустыми. Переписать число **B2**.
4. Проверить, что виджет действительно привязан к `period` на `dim_date.full_date`, а запрос читает `retail_pz7.fact_sales` (не сводку З09).

## Шаг 3. Сверить

Подставить **реально увиденные** значения вместо примеров:

```powershell
py -3.11 pz11/scripts/verify_sql_bi.py --bi-all 264 --bi-jan ВАШЕ_ЧИСЛО_ЗА_ЯНВАРЬ
```

Числа можно передать с десятичной точкой или запятой (для запятой заключить аргумент в кавычки). Скрипт сравнивает `Decimal` с точностью до 0.01 и заполняет `pz11/checks/results.md` реальными результатами. Если цифры различаются, будет `FAIL`: сначала проверить условия фильтра, SQL, источник и тип `Decimal`, а не менять вручную значение карточки.

## Условия и вывод

| Сценарий | Даты | Регион | Магазин | Дополнительные фильтры |
|---|---|---|---|---|
| А: без фильтров | Все даты | Все | Все | Нет |
| Б: январь 2024 | 01.01.2024–31.01.2024 включительно | Все | Все | Нет |

Оба SQL используют ту же бизнес-формулу `SUM(amount)`. При выборе периода в Metabase используется Field Filter по `dim_date.full_date`. Сумма из `agg_daily_store_sales` может служить дополнительной проверкой, но не является эталонной метрикой.
